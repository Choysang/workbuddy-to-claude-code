# Spec Trace — 需求文档对照交付循环

GIS7 V1 交付流程固化（docs/codex/REQ_TRACEABILITY.md 模式）。核心：**先清单，后拍板，再代码，收口有测试锁。**

## 流程

1. **提取规格（全量）**：docx 正文 + 内嵌 OLE/xlsx 全部展开——`python-docx` 读正文，zipfile 解 `word/embeddings/` 取内嵌表。教训：GIS7 曾两次宣布"V1 收口"，都被内嵌对象里的 25 条脚本规格 + 27 列表规格打脸。只读正文 = 必漏。
2. **先清单后代码**：输出对照清单等用户确认——列：规格条目｜适用域(4G/5G等)｜当前代码有无(文件:行)｜缺口｜需拍板项。**确认前不写代码。**
3. **拍板项一次列全**：阈值、AND/OR、单位、字段来源、缺失处理、时段窗口——编号清单一次问完，不挤牙膏。
4. **实现**：低风险先做；小步提交每步 build GREEN + 回归测试；缺字段 N/A 不伪造；"当前值≠目标值才生成"类条件必须真读当前值判断，查不到当前值就按模板输出 + Remark"当前值未知，执行前需核查"，不许假装判断过。
5. **收口**：更新追溯矩阵 + HANDOFF（含全部已拍板口径）；给每个已裁定值加回归测试锁住防漂移；矩阵全绿才可以说"收口"。

## 红线

- 文档规范 vs 代码现状冲突 → 按文档，除非用户拍板改文档。
- 规格"只可以多不可以少"：实现超出文档可以，少于文档必须列缺口。
- HANDOFF 里已关闭的项（如 B7 启动性能=不再优化）不许重新打开重查。
