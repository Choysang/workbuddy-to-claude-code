# /verify

验收范围：$ARGUMENTS（留空则用本次会话的目标）。

## 步骤

1. 把需求整理成可判定的条目清单，保持原始措辞，不要改写成"已完成"的口吻。
2. 派 `verifier` 独立验证：给它条目清单、相关文件路径、可运行的检查命令。
3. 汇总结论，每条只允许四种状态：
   - **已验证通过**：附命令与输出
   - **行为失败**：附反例
   - **环境失败**：附原因
   - **未运行**：附原因
4. 对行为失败项直接修，修完只重跑受影响的检查。

## 禁止

用"代码看起来对"或"实现者说已完成"作为通过依据。退出码 0 不等于产物正确，配置能解析不等于生效。
