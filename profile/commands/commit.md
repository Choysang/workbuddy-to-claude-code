argument-hint: "可选：提交范围或说明"
---

<user_input>
$ARGUMENTS
</user_input>

1. `git status` 与 `git diff` 确认将要提交的内容；检查有没有把密钥、日志、构建产物、无关文件带进去。
2. 跑与改动匹配的检查（测试、lint、构建），失败就停下来说明，不要提交。
3. 提交信息写"为什么改"，第一行简短，必要时正文补背景；不要写"update files"。
4. 报告：提交哈希、改了什么、跑了什么检查、还有什么没验证。

不要 push、不要 force-push、不要改写已有提交，除非用户明确要求。
