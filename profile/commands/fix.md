# /fix

问题：$ARGUMENTS

## 步骤

1. **复现**。拿到最小可复现命令或步骤。复现不了就先解决"为什么复现不了"，不要猜。
2. **定位**。原因不明时派 `debugger`；它给出的根因必须能解释现象，不能只是"可能"。
3. **最小修复**。只改导致问题的那一处，不顺带重构。修根因，不修症状（不加 try/except 把错误吞掉、不加 sleep 绕过竞态）。
4. **验证**。重跑复现命令确认转绿；再跑受影响范围的测试。回归用例该补就补（可派 `test-author`）。
5. **交代**。如果根因涉及更大的设计问题，单独写出来，不要在这次修复里顺手改。

## 禁止

- 用 `--no-verify`、跳过测试、放宽断言来让结果变绿。
- 修复后不重跑复现命令就宣布完成。
- 把"加了个判断让它不报错"当成修复。

## 返回

现象 → 最小复现 → 根因 → 改动（`file:line`）→ 验证命令与结果 → 同类问题是否还存在。
