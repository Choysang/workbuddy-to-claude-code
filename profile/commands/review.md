# /review

审查范围：$ARGUMENTS（留空则工作区与暂存区 diff，并包含未跟踪的新文件）。

## 步骤

1. 先看 `git status --short`、`git diff`、`git diff --staged`。对范围内未跟踪的新文件，用 Read 读取实现；只有三类内容都为空才说明没有可审内容。不要将未跟踪文件遗漏出审查范围。
2. 读每个改动点的上下文（调用方、被调方、错误处理、事务边界），不只看改动行。
3. 派 `code-reviewer` 做独立一轮；关键结论自己复核，不要直接转述。
4. 按严重度排序输出。

## 每条格式

`file:line` → 触发条件 → 实际后果 → 最小修复方向。

## 判定标准

只报能指出触发条件的缺陷：正确性、并发、资源、边界、静默失败、契约破坏、有量级依据的性能退化。

不报：命名、格式、个人风格偏好、"可以更优雅"、与本次改动无关的历史问题。

## 返回

结论（可合并 / 需修改 / 有阻塞）→ 问题清单（按严重度）→ 已验证的部分 → 未覆盖的部分。
