# /handoff

交接目标：$ARGUMENTS（留空则写 `.harness/HANDOFF.md`）。

## 步骤

1. 先核对磁盘真实状态：`git status`、关键文件是否存在、最后一次验证命令的结果。不要凭记忆写。
2. 按下面结构写文件（覆盖写，不追加历史流水）。

## 结构

```markdown
# <任务名> 交接

## 目标
一句话，含验收标准。

## 当前状态
已完成 / 进行中 / 阻塞，各一句。

## 已做的决定
- 决定：<内容> — 理由：<一句> — 影响：<哪个文件/接口>

## 变更清单
- `path:line` — 改了什么

## 验证结果
- 命令：<命令> → <结果>
- 未验证：<项> — 原因：<原因>

## 剩余工作
1. <可执行的下一步>

## 坑
- <踩过的坑，一句话一条>
```

## 规则

- 只写对下一个接手者有用的信息，不写过程叙述。
- 未验证的项必须显式列出，不要用"应该没问题"。
- 不写密钥、令牌、个人路径以外的敏感信息。
