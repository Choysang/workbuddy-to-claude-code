# /design

设计目标：$ARGUMENTS

只做设计与规划，不修改任何文件。

## 步骤

1. 复述目标，并明确写出**不做什么**。
2. 读相关代码与项目约定，列出受影响的文件、调用方、共享状态。
3. 派 `architect` 做独立方案，重点要它给出契约与被否决的替代方案。
4. 你复核它的每个事实断言（指不到 `file:line` 的不算证据），再定稿。

## 产出

- **结论**：采用什么方案，一段话。
- **改动面**：按文件列出改什么、谁负责。
- **契约**：接口签名、数据结构、配置键、错误语义。
- **步骤**：可执行的序列，标出可并行与必须串行的部分。
- **验收**：每步怎么验证做对了。
- **风险**：失败模式与回滚方式。
- **待定**：需要用户拍板的选项，附默认建议。

计划要能被别人直接执行。不要写"优化代码结构""提升可维护性"这类无法验收的步骤。
