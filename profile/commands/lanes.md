# /lanes

任务：$ARGUMENTS

## 步骤

1. **先判断能否并行**：子任务之间没有文件重叠、没有先后依赖、验收各自独立。不满足就老实串行，并说明为什么。
2. **拆车道**。每条写清：
   - 目标（一句话，可判定）
   - 允许改动的文件（精确路径或目录）
   - 不要碰的文件
   - 依赖的接口契约（签名、数据形状）
   - 验收命令
3. **同一条消息里同时派出**多个 `lane-worker`；需要完全隔离（同文件竞争、试验性改动）时用 `worktree-worker`。
4. **收口**：检查越界改动、接口一致性、文件冲突，再跑一次整体检查。
5. **汇总**：每条车道的实际改动、验证结果、需要主会话决策的事项。

## 规则

- 不为并行而并行。串行更快时就串行。
- 共享接口只让一条车道负责，其他车道按契约调用。
- 车道之间不允许互相等待；有依赖就合并成一条车道。
- 任何车道报告失败，先判断是否阻塞其他车道，再决定合并顺序。
