# /audit

对 $ARGUMENTS 做一次对抗式审计。默认范围：当前工作区全部代码。

## 步骤

1. **建立基线**：项目结构、构建/测试命令、入口。跑一次现有测试，记录真实状态（不是 README 声称的状态）。
2. **拆需求**：有需求文档就逐条拆成可判定条目；没有就从代码与文档反推「应该做到什么」，并标注这是推断。
3. **并行取证**：
   - `verifier`：逐条判定需求是否真的实现，附可执行证据。
   - `silent-failure-hunter`：找出错但没人知道的路径。
   - `code-reviewer`：审查核心路径。
4. **自己复核**任何"通过"的结论。子代理说通过但拿不出命令输出的，一律记为未验证。
5. **查缺补漏**：未实现的条目、只写了一半的路径、TODO/FIXME 堆积、被跳过的测试、注释掉的断言。

## 输出

| 条目 | 状态 | 证据 |
| --- | --- | --- |

状态只有四种：已验证 / 失败 / 环境阻塞 / 未运行。

然后：阻塞项清单（按影响排序）→ 建议的修复顺序 → 明确列出本次审计没有覆盖的范围。

## 禁止

用"看起来实现了"代替运行证据。为了让报告好看而省略失败项。
